## B6 specification (unchanged)

The only open point in the whole revision. Nothing in the paper is missing or wrong: the Limitations concede in full that the model has very likely seen the public data dictionaries, forum discussions and winning-solution write-ups, so part of its ranking may reflect memorised public knowledge rather than reasoning from feature meaning, and that the definition-only prompt withholds every statistic but not the public names and descriptions. The prompt itself already instructs "Do not use external sources or remembered dataset-specific results to fill gaps" (Appendix A), but an instruction cannot verify itself and must not be presented as a control; changing the prompt now would also invalidate every cached ranking and add a protocol version to Table 2. The open question is how a referee reads the contribution: semantic pre-screening, or recognition of familiar feature names. The existing defence is that Stability 2024's engineered features and approved definitions are specific to this study and the LLM leads there under both backbones. An obfuscation run would settle it: replace names with `F001 ...`, keep descriptions, re-rank, refit, score on HO. Home Credit alone is enough: **six ranking calls of 100 names, one per partition** (five folds plus full DEV), because Section 4.4 records that the Home Credit budgets of 20, 40, 60 and 100 are prefixes of one ranking per partition, not separate calls per budget; then twelve refits (top 20 to logistic regression, top 40 to CatBoost, five folds plus the full-DEV refit each) and HO scoring on the same 120,053 rows. The second-opinion read of 2026-09-14 (Section 3, major 2) adds a second arm at the same cost: **names kept, descriptions removed**. Run together the two arms attribute the signal between the name channel and the description channel instead of only weakening the first. Everything except the feature records must be identical: snapshot `gpt-4.1-mini-2025-04-14`, temperature 0, JSON response format, the Appendix A template unchanged, `definitions_only`, the same eligible candidate set per fold (365 to 374 of 529), the same five folds, the same strict validation (exactly 100 distinct names present verbatim, up to three retries, no fallback). Two traps void the result if missed: every literal occurrence of the original name must be scrubbed from inside the description text as well as the name field, or a record still reads `EXT_SOURCE_3` in its own definition; and the identifiers must be assigned by a seeded shuffle rather than alphabetical or file order, with the seed recorded, or the ordering leaks the structure back.
